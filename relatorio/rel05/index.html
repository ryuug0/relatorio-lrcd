1 Introdução

Este relatório aborda o desenvolvimento de um pacote de funções para o ambiente R. O pacote graf criado consta com 3 funções principais: git(), mpot() e mdes(), que serão abordadas a seguir. Apesar do nome ser “graf”, o pacote não se trata de análises gráficas. O nome é apenas um resquício da proposta inicial do projeto, que foi descartada por já existirem pacotes consolidados para gráficos, como leem, ggplot2 e as próprias funções nativas do R. O foco estabelecido foi a resolução de problemas práticos de automação e engenharia.

2 Instalação e Documentação do Pacote

Antes de utilizar as funções, o pacote necessita ser documentado e instalado localmente no ambiente R. A estruturação foi realizada utilizando o pacote roxygen2. Através de comentários no código-fonte iniciando com #' e tags específicas como @param e @export, a documentação é automatizada.

Para efetivar a instalação, utilizam-se dois comandos do pacote devtools diretamente no console:

  1. devtools::document(): Processa as marcações do roxygen, gera os manuais de ajuda das funções e escreve o arquivo NAMESPACE. Isso garante que as funções sejam exportadas corretamente, evitando conflitos de escopo no R.
  2. devtools::install(): Compila o projeto e instala o pacote fisicamente na biblioteca local da máquina.

Após essas etapas, o pacote é ativado para uso na sessão atual:

library(graf)

3 Funções

3.1 git()

Esta função foi criada baseada nos problemas enfrentados ao publicar os relatórios da disciplina na página do GitHub. Como o repositório é composto por um aninhamento de várias pastas contendo arquivos index.qmd e index.Rmd, a renderização manual causava diversos bugs, resultando em arquivos desatualizados na página final.

A ideia para solucionar e automatizar esse problema foi criar uma função que, a partir da pasta raiz do projeto, faça uma busca recursiva em todas as pastas filhas rodando quarto render nos arquivos .qmd e o comando nativo de renderização nos arquivos .Rmd. Isso garante que todo o projeto seja compilado. Além disso, a função engloba os comandos de terminal do Git (add ., commit e push), permitindo commits sem comentários por meio da flag --allow-empty-message, o que facilita testes rápidos que exigem publicação.

A seguir, o código da função detalhado por etapas:

Renderizando todos os .qmd do projeto:

meu_git <- function(msg) {

  arquivos_qmd <- list.files(pattern = "\\.qmd$", recursive = TRUE, full.names = TRUE)
  if (length(arquivos_qmd) > 0) {
    message("=> Passo 1: Renderizando todos os arquivos .qmd...")
    for (qmd in arquivos_qmd) {
      message(paste("-> Renderizando:", basename(qmd)))
      system(paste("quarto render", shQuote(qmd)))
    }
  }

“Costurando” todos os .Rmd do projeto:

  arquivos_rmd <- list.files(pattern = "\\.[Rr]md$", recursive = TRUE, full.names = TRUE)
  if (length(arquivos_rmd) > 0) {
    message("=> Passo 2: Knitando todos os arquivos .Rmd...")
    for (rmd in arquivos_rmd) {
      message(paste("-> Knitando:", basename(rmd)))
      rmarkdown::render(rmd, quiet = TRUE)
    }
  }

Sincronizando o projeto com o GitHub:

  message("=> Passo 3: Enviando tudo para o GitHub...")
  system("git add .")

  comando_commit <- sprintf('git commit --allow-empty-message -m "%s"', msg)
  system(comando_commit)

  system("git push")
  message("=> Feito! Tudo atualizado e no ar.")
}

3.2 mpot()

A próxima função implementada no pacote resolve um problema diário enfrentado no meu estágio na oficina de motores elétricos. Lido com a identificação desses equipamentos e muitos chegam com a placa de identificação danificada, o que atrapalha o fluxo de manutenção. Vários parâmetros nominais são dependentes, e a potência pode ser obtida através da tensão nominal, corrente nominal, fator de potência, rendimento e número de fases. A ideia futura é escalar o pacote para cruzar esses dados e identificar o motor em catálogos. No momento, o escopo se concentra no cálculo da potência.

A potência elétrica ativa é dada, em kW, pela fórmula:

\[P_{kW} = \sqrt{3} \cdot V \cdot I \cdot F_P \cdot \eta\]

Para converter o valor para Cavalos-Vapor (CV):

\[P_{cv} = P_{kW} \cdot 1,36\]

A função implementada identifica o número de fases para adaptar a fórmula (o fator \(\sqrt{3}\) é utilizado apenas em motores trifásicos) e verifica se o rendimento (\(\eta\)) foi inserido. Essa verificação define se o retorno será a potência elétrica consumida ou a potência mecânica real entregue no eixo:

meu_mpot <- function(f, v, i, fp, rendimento) {
  fator <- ifelse(f == 3, sqrt(3), 1)
  p_kw <- (fator * v * i * fp) / 1000

  if (is.null(rendimento)) {
    tipo <- "Potência Elétrica Ativa"
  } else {
    tipo <- "Potência Mecânica no Eixo"
    p_kw <- p_kw * rendimento
  }

  p_cv <- p_kw * 1.35962

  list(
    Tipo = tipo,
    kW = round(p_kw, 2),
    CV = round(p_cv, 2)
  )
}

Exemplo de uso nativo para um motor trifásico, com tensão nominal de 380 V, corrente nominal de 21.5 A, fator de potência de 0.92 e rendimento de 97%:

mpot(f = 3, v = 380, i = 21.5, fp = 0.92, rendimento = 0.97)
$Tipo
[1] "Potência Mecânica no Eixo"

$kW
[1] 12.63

$CV
[1] 17.17

3.3 mdes()

Esta função também foca em motores elétricos, mas voltada para análise de falhas operacionais. Ela avalia o desbalanceamento de corrente entre as fases baseado em dados obtidos por medição direta. Acima de 5%, a assimetria apresenta risco severo de degradação térmica à integridade do motor.

O teste imposto pela norma NEMA utiliza a média das correntes como parâmetro comparativo. Porém, na oficina de campo, utilizamos a razão direta entre o maior e o menor valor medido. Isso eleva a sensibilidade do cálculo e garante uma margem de segurança maior para o equipamento do cliente.

O cálculo implementado é baseado na fórmula:

\[D_{\%} = \left(\frac{I_{max}}{I_{min}}-1\right)\cdot 100\]

A função contém um gatilho condicional para disparar um alerta de segurança se o limite de 5% for excedido:

meu_mdes <- function(correntes) {
  n <- length(correntes)

  if (n == 1) {
    warning("Motores monofásicos não possuem desbalanceamento de fase.")
    return(NA)
  } else if (n >= 2) {
    desbal <- (((max(correntes) / min(correntes)) - 1) * 100)
  }

  if (!is.na(desbal) && desbal > 5) {
    warning("ALERTA: Desbalanceamento acima de 5% (risco de superaquecimento).")
  }

  return(round(desbal, 2))
}

Exemplo prático de execução identificando um motor com desequilíbrio crítico nas correntes medidas de 13.0 A, 14.5 A e 17.2 A:

correntes_lidas <- c(13.0, 14.5, 17.2)
mdes(correntes_lidas)
Warning in meu_mdes(correntes): ALERTA: Desbalanceamento acima de 5% (risco de
superaquecimento).
