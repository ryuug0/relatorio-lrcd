1 Introdução

Este relatório aborda o desenvolvimento de um pacote de funções para o ambiente R. O pacote graf conta com três funções principais: git(), mpot() e mdes(), que serão detalhadas a seguir. Apesar do nome, o pacote não realiza análises gráficas; trata-se de um resquício da proposta inicial do projeto, descartada devido à existência de ferramentas mais robustas para esse fim, como leem, ggplot2 e as funções nativas do R.

2 Funções

2.1 git()

Esta função foi desenvolvida para solucionar problemas recorrentes na publicação dos relatórios da disciplina no GitHub. A estrutura do projeto consiste em várias pastas aninhadas contendo arquivos index.qmd e index.Rmd, o que causava falhas de compilação e impedia a atualização correta da página web.

Para automatizar a solução, a função realiza uma busca recursiva a partir da pasta raiz do projeto, executando quarto render nos arquivos .qmd e rmarkdown::render nos arquivos .Rmd. Isso garante a compilação integral do projeto. Em seguida, a função executa a esteira do Git (add, commit e push), permitindo commits sem mensagem explícita para agilizar testes e atualizações frequentes.

Abaixo, a estrutura do código da função dividida em etapas:

Renderizando todos os .qmd do projeto:

  meu_git <- function(msg) {

  arquivos_qmd <- list.files(pattern = "\\.qmd$", recursive = TRUE, full.names = TRUE)
  if (length(arquivos_qmd) > 0) {
    message("=> Passo 1: Renderizando todos os arquivos .qmd...")
    for (qmd in arquivos_qmd) {
      message(paste("-> Renderizando:", basename(qmd)))
      system(paste("quarto render", shQuote(qmd)))
    }
  }

Processando (“Knitando”) todos os .Rmd do projeto:

  arquivos_rmd <- list.files(pattern = "\\.[Rr]md$", recursive = TRUE, full.names = TRUE)
  if (length(arquivos_rmd) > 0) {
    message("=> Passo 2: Knitando todos os arquivos .Rmd...")
    for (rmd in arquivos_rmd) {
      message(paste("-> Knitando:", basename(rmd)))
      rmarkdown::render(rmd, quiet = TRUE)
    }
  }

Sincronizando o projeto com o GitHub:

  message("=> Passo 3: Enviando tudo para o GitHub...")
  system("git add .")

  comando_commit <- sprintf('git commit --allow-empty-message -m "%s"', msg)
  system(comando_commit)

  system("git push")
  message("=> Feito! Tudo atualizado e no ar.")
}

2.2 mpot()

A segunda função implementada automatiza um cálculo diário do meu estágio com motores elétricos. Frequentemente, a placa de identificação desses motores está danificada. Contudo, como vários parâmetros são interdependentes, é possível calcular a potência a partir da tensão nominal, corrente nominal, fator de potência, rendimento e número de fases. Embora o cálculo seja simples, o objetivo a longo prazo é escalar o pacote para cruzar esses dados com catálogos e identificar o modelo exato do equipamento. Por enquanto, o escopo da função limita-se ao cálculo da potência.

A potência elétrica ativa do motor é dada, em kW, pela fórmula:

\[P_{kW} = \sqrt{3} \cdot V \cdot I \cdot F_P \cdot \eta\]

Para converter o resultado em cavalos-vapor (CV):

\[P_{cv} = P_{kW} \cdot 1,36\]

O código avalia o número de fases para adaptar a fórmula (o fator \(\sqrt{3}\) é exclusivo para sistemas trifásicos) e verifica se o rendimento (\(\eta\)) foi informado, determinando se o retorno representa a potência elétrica da rede ou a potência mecânica na ponta do eixo:

meu_mpot <- function(f, v, i, fp, rendimento) {
  fator <- ifelse(f == 3, sqrt(3), 1)
  p_kw <- (fator * v * i * fp) / 1000

  if (is.null(rendimento)) {
    tipo <- "Potência Elétrica Ativa"
  } else {
    tipo <- "Potência Mecânica no Eixo"
    p_kw <- p_kw * rendimento
  }

  p_cv <- p_kw * 1.35962

  list(
    Tipo = tipo,
    kW = round(p_kw, 2),
    CV = round(p_cv, 2)
  )
}

Exemplo prático de uso para um motor trifásico com tensão de 380 V, corrente de 21,5 A, Fator de Potência de 0,92 e rendimento de 97%:

Código 
library(graf)
mpot(3, 380, 21.5, 0.92, 0.97)
$Tipo
[1] "Potência Mecânica no Eixo"

$kW
[1] 12.63

$CV
[1] 17.17

2.3 mdes()

Esta função também é voltada para motores elétricos, mas focada na análise de falhas operacionais. Ela avalia o desbalanceamento de corrente entre as fases, condição que, ao ultrapassar o limite de 5%, compromete a integridade térmica do estator.

Enquanto a norma NEMA baseia o cálculo nos desvios em relação à média das correntes, a abordagem implementada no pacote utiliza a razão direta entre a maior e a menor corrente medida. Esse método é adotado na prática de manutenção de campo por ser mais conservador e sensível, garantindo uma resposta de segurança mais rápida.

O cálculo executado é dado pela fórmula:

\[D_{\%} = \left(\frac{I_{max}}{I_{min}}-1\right)\cdot 100\]

meu_mdes <- function(correntes) {
  n <- length(correntes)

  if (n == 1) {
    warning("Motores monofásicos não possuem desbalanceamento de fase.")
    return(NA)
  } else if (n >= 2) {
    desbal <- (((max(correntes) / min(correntes)) - 1) * 100)
  }

  if (!is.na(desbal) && desbal > 5) {
    warning("ALERTA: Desbalanceamento acima de 5% (risco de superaquecimento).")
  }

  return(round(desbal, 2))
}
